# Source photographs of the actual house

**What this is:** photos I took myself of the real house on the site (the building that the
Datasmith model in `source/3d-datasmith/` describes). These are the *ground truth* input of
the project: whatever the pipeline generates must stay consistent with these.

They are used for:

- checking that the 3D model matches what was actually built (geometry, window/door positions,
  façade proportions, roof form);
- reference material for façades and surroundings (as style/photo reference for approach B,
  and as the "before" column of the before/after gallery in `PROJECT.md` § 3);
- crops for the optional own-material LoRA (plaster / brick / wood samples, § 6 task 8).

## Current contents

14 aerial frames from a DJI drone (FC3582), 4032×2268, flat in this folder, named `DJI_*.JPG`
(as shot). They are views of the whole house from several angles — the naming convention below
has not been applied to them; they are drone frames, not per-façade documentation shots. Two
dates are present (27.10 and 30.10), which is the “how it looked at that moment” distinction
this folder cares about.

Each file is an MPO (two frames: the drone writes a second, slightly different frame next to
the JPEG). The prepared copies take the first frame only.

### `web/` — generated by `python scripts/photos.py`

| file | what it is |
|---|---|
| `web/DJI_* .jpg` | EXIF/GPS removed by re-encoding, long side 2048 px, quality 88 (46.4 MB → 6.4 MB for 14 frames) |
| `web/contact_sheet.jpg` | 4×4 overview with the original file name under each frame |
| `web/MANIFEST.md` | per-file record: original size, prepared size, bytes, whether the original carried GPS, sha1 of the prepared file |

Verified after generation: the prepared files contain **0 EXIF tags and no GPS block**, while
the originals still have 14 tags and GPS. The originals in this folder are the working files
that ComfyUI reads (copies of the four frames used by the graphs also sit in
`<ComfyUI>/input/`); the `web/` copies are what the public repo and the gallery should use.

```
  reference/           old photos (pre-construction, plan PDF scans, ArchiCAD printouts)
```

Only add subfolders that actually get used — empty folders are not tracked by git.

## Naming convention

`<side-or-room>_<viewpoint>_<yyyymm-dd>[.<desc>].jpg`, e.g.

```
facade_front_20261025.jpg
facade_garden_20261025_west-angle.jpg
interior_livingroom_20261025.jpg
details_plaster_20261025_closeup.jpg
```

Note the date: the house is under construction, so "how it looked at the time of the photo"
matters when comparing renders against reality.

## Before committing (important for a public repo)

1. **Strip EXIF/GPS** — the originals carry the exact site coordinates, which would defeat the
   anonymization already done for the Datasmith copy (see `source/3d-datasmith/README.md`).
   Done for the committed copies by `scripts/photos.py` (Pillow: re-encoding without asking for
   EXIF drops camera data and coordinates together; no ExifTool needed). The originals keep
   theirs. For other files: `exiftool -all= -overwrite_original <file>`.
2. **Check for people, car plates, house numbers, street signs** in frame and crop/blur them.
3. **Sizes**: commit resized JPEGs (long side ~2048 px) for the repo/gallery; keep full-res
   and RAW out of git. If you want RAW kept, add its extension to `.gitignore` **before**
   the first photo is ever committed (git keeps tracking files already added).
4. These are my own photos, so publishing them is unproblematic licensing-wise — but they are
   the one asset in the repo where privacy (not license) is the thing to check.
